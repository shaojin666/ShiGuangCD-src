# ShiGuangCD v10.9.1 更新说明

本次更新是**全屏歌词演出层的微调轮**：专辑封面归位到二级菜单、菜单底部并排、新增选歌功能、运镜拉近 + 歌词间穿梭。变更共涉及 **10 个文件**（1 个新增 + 9 个修改 + package.json 版本号 1.8.0 → 1.8.1 + 本说明）。演出层本身零新增运行时依赖。

---

## 一、专辑封面移入二级菜单（大号 + 歌名/艺术家）

- **位置**：右下角三个点按钮的菜单**内部**最上方（不再是按钮上方的小图），位于**播放/切歌按钮上方**——菜单从下往上弹出，封面 → 歌名/艺术家 → 播控 → 音量 → 底部并排项，视觉动线自然。
- **尺寸**：**176×176 大号封面**（圆角 14px），有封面显图、无封面露占位光盘（`has-cover` 门控，封面 URL 仍走 `coverUrlOf()`，signature 缺失不拼坏 URL）。
- **歌名/艺术家**：封面**下方**居中显示，大字号、超长省略号；与胶囊信息同源（`syncInfo` 一次同步）。
- **菜单加宽** 232px → **272px**，底边从 136px 抬到 **78px**，保证大封面也不遮挡菜单钮。

## 二、播放顺序与弹出光盘并排最下方

- 原竖排的两个菜单项改为底部**一行两个**（`.fl-menu-item.half`，各占一半宽、12.5px 小字 + 图标）：左「顺序播放」（新增循环箭头图标，点击轮换播放模式）、右「弹出光盘」（先撤演出层再发 `cd:eject`，退碟仪式不被盖住）。

## 三、选歌功能（新面板 + 快捷键 L）

- **入口**：演出层顶栏新增「选歌」按钮（购物篮图标，`title` 提示「选歌 (L)」），快捷键 **`L`**；`Escape` 层级：主题面板 → **选歌面板** → 菜单 → 退出演出层。
- **数据源纪律**：曲目数与时长以 **TOC 为权威**，元数据只补标题/艺术家（合并同一曲目号）；`byNum` 合并，缺元数据也不丢行。
- **行内容**：序号（`01` 补零）+ 歌名/艺术家 + 时长；**当前曲目金色高亮**并 `scrollIntoView({block:'nearest'})` 跟进。
- **切歌链路与主界面完全相同**：`App.playTrack(n)`（Transport.optimisticTrack + `cd:play-track` IPC），切完自动关面板。
- **身份不变不重建**：`sync()` 按曲目号拼接签名比对，换歌/进元数据只更新高亮，不重建 DOM；面板外点击自动关闭（capture 阶段）。

## 四、运镜拉近 + 在 3D 歌词间穿梭

针对「歌词距离太远、字太小看不清」：

- **拉近几何**：Warp 行距 Z 系数 **-110px → -64px**；Halo 圆环半径 **620px → 380px**。同样的字号，离观众近了一大截。
- **拉近运镜**：两主题 rig 的推近/升降/鼓点/入场幅度整体上调（warp：dolly 26、bassPush 14、pulsePush 6；halo：dolly 18、bassPush 10、pulsePush 4）。
- **穿梭（dash）**：rig 的 cut 通道从「单轴鞭打」扩为**五通道**（yaw/pitch/push/x/y）。换行切镜时在鞭打之外追加：
  - **正向冲刺**（`dashPush`）：歌词向观众涌来，像镜头扎进行间；
  - **横向闪避**（`dashX`）：左右交替，逐行编织出「之」字形轨迹；
  - **微沉**（`dashY`）：过门时镜头轻轻一坠。
  - GSAP 一次性编排（1.15s power3.out），**不进逐帧热路径**；幅度走 `amp('dash', 1)`，与既有滑条管线同律。
- **「穿梭强度」参数**（0–2.4×，默认 1）：参数滑条新增一项，**拉到 0 即整体关闭**，观感回退到 v10.9 的纯鞭打——不想要穿梭的用户有干净开关。

### 实测抓到并修掉的坑

1. **封面被逐帧冲掉**（截图脚本侧）：`syncInfo` 每帧用 `cover://` URL 覆写菜单封面背景，而浏览器桩没有该协议处理器 → 截图用 `page.route` 拦截止 `cover://` 返回渐变 SVG；stub 的 `hasCover` 改 true（jsdom/ui-contract 仍锁定 URL 规则本身，两不干扰）。
2. **暂停态 chrome 自动隐藏**：点菜单/选歌钮前 `page.click` 超时 → 脚本先 `mouse.move` 唤醒 chrome（渲染端行为本来就对，是脚本时序问题）。
3. **采样脚本正则转义**：`page.evaluate` 传模板字符串时 `\\(` 被双重转义 → 改为 Node 侧真实函数直接传入。
