## Bug：专辑封面点击 / 播放按钮点击无任何反应

用户实测「点封面没反应、点播放按钮也没反应」，导致专辑详情页完全无法进入。排查发现这是**两个独立根因叠加**，任缺其一点击就死：

### 根因 A：pointerdown 里立即 setPointerCapture，吞掉所有子元素 click

Chromium 的既有行为：一旦在 `pointerdown` 里对容器调用 `setPointerCapture(container)`，随后的 mousedown / mouseup / **click** 会全部重定向到捕获目标（容器）——子元素（封面项、播放按钮）的 click 永远不触发。原 `wireFlowPointer` 为了拖动跟手，在 pointerdown 里就捕获了指针，等于把点击语义判了死刑。

**修复**（`renderer/js/library.js`）：改为**延迟捕获**——pointerdown 只记录 `pending` 状态，只有 `pointermove` 越过 `DRAG_SLOP`（6px）阈值、确认是拖动后才 `setPointerCapture`；阈值之内不捕获、不位移，完整保留正常点击语义。pointerup 时若从未进入拖动（`!wasDragging`）直接返回，不抢焦点。

### 根因 B：album.js 用 const 定义，window.Album 恒为 undefined

经典脚本顶层的 `const Album = ...` 只进入全局词法环境——裸标识符 `Album` 能被其他脚本解析，但**不会产生 `window.Album` 属性**。而 `library.js` / `app.js` 里全是 `if (window.Album)` 守卫，守卫恒假，封面点击、回车打开、Esc 关闭全部静默失效。（`lyrics-view.js` 用的是 `window.LyricsView = ...` 模式所以一直正常。）

**修复**（`renderer/js/album.js` 末尾）：`window.Album = Album;`，与 `window.LyricsView` 模式对齐。

### 回归固定

`tests/renderer.test.js` 新增 **#25 CoverFlow 点击回归**（jsdom 行为级）：阈值内不捕获、点击封面打开详情页、过阈值才捕获、拖动跟手、拖动后的 click 被抑制、播放按钮 click → `App.requestDisc`、信息行文本。测试里补了 jsdom 缺失的 `setPointerCapture` spy 与 `DOMMatrixReadOnly` 桩。

## 需求 1：CoverFlow 专辑名下移 + 信息行

- **下移**（`renderer/css/pages.css`）：`.lib-flow-top` 高度 56px→48px、`margin: 2px 44px 0`→`margin: 16px 44px 0`，专辑名整体下移约 14px，封面居中区域视觉更平衡。
- **信息行**：专辑名下方新增 `.lib-flow-meta`（`#lib-flow-meta`），12.5px 弱化色，超长省略。内容为 **艺术家 · 年份 · 碟号 · 歌总数**，例如 `测试艺术家 · 2020 · 3 首`：

  - 封面项上挂 `__meta` expando（`buildFlowItem`），避免每帧扫 `_lastItems`；
  - `updateFlowChrome` 焦点变化时同步刷新，空库分支清空。

## 需求 2：逐字歌词英文空格被吞（"I love you" → "Iloveyou"）

这是之前遗留问题。分词本身正常，但空格消失。**三层原因**：词 span 是独立元素，浏览器不会在元素之间补空格；`main/lyrics/schema.js` 的 `str()` 对词文本 `.trim()` 掉自带空格；解析层修了也会被 schema 抹掉——唯一有效修复层是渲染层。

**修复**（`renderer/js/lyrics-view.js`）：新增 `needsSpace(prev, cur)` 启发式 + `appendWords`——在相邻词 span 之间插入空格文本节点：

- 两侧均为拉丁字母/数字（含拉丁扩展 `U+00C0–U+024F` 与西里尔 `U+0400–U+04FF`）→ 补空格（`I love you`、`don't stop`）；
- 任一侧已带空白、或任一侧以连字符相接 → 不补（`singer-songwriter`）；
- CJK 之间不补（中文歌词原本正常，不能引入多余空格）。

主词与背景人声（对唱）两条渲染路径都走 `appendWords`。`tests/renderer.test.js` **#26c 英文空格回归**用四行数据固定契约（英文补 / CJK 不补 / 撇号补 / 连字符不补）。

## 需求 3：播放顺序、音画律动保存到本地

- **播放顺序**：原来 `cd:set-mode` 只改 CdService 内存，重启回到 normal。现在 `main/ipc.js` 的 handler 落盘 `settings.update({ playMode: next })`；`main/index.js` 默认值声明 `playMode: 'normal'`；`main/cd/cd-service.js` 构造时 `this.playMode = (this.settings && this.settings.playMode) || 'normal'` 恢复——经 `cd:get-state` 的 `mode` 字段送到渲染端 `restoreState` → `setMode(mode, true)`（静默模式不发 IPC）→ 按钮标签。
- **音画律动**：`renderer/js/settings.js` 的 toggle 补 `settings:set({ visualFx: next })` 落盘；主进程默认值 `visualFx: true`。

## 需求 4：读盘界面弹出托盘按钮

- **形态**（`renderer/index.html` + `renderer/css/scene.css`）：`#ceremony-sub`（"等待光盘"）下方新增 `#ceremony-eject` 玻璃胶囊按钮，含弹出图标 + "弹出托盘"文字；**默认隐藏**（`opacity: 0` + 轻微下沉缩放），鼠标靠近（感应半径 110px）时 `.near` 淡入；只在待机阶段（`#ceremony.ph-idle`）可用，其它阶段 `display: none`。
- **交互**（`renderer/js/app.js`）：新增 `wireCeremonyEject()`——点击走 `window.cd.invoke('cd:eject')`；复用 `#ceremony-exit`（退出按钮）既有的 document mousemove 距离判定范式；按钮不可见时（`getBoundingClientRect().width === 0`）自动跳过判定。

## 需求 5 / 6：设置页新增两个开关（默认均关）

设置面板「系统」区顶部新增（`renderer/js/settings.js`，沿用既有 `toggle()` helper）：

- **开机自动启动**：写入系统登录启动项。toggle 同时做两件事——`settings:set({ autoLaunch })` 落盘（权威态）+ `app:set-auto-launch` 同步 OS 项（即时生效，不等重启）。`main/ipc.js` 新增对应 handler（`app.setLoginItemSettings({ openAtLogin: on })`，`preload.js` 白名单放行）；`main/index.js` 启动时**只"确保开"**（设置开着才同步 OS 项，关着不擅自删——关闭只由显式 toggle 负责）。
- **进入时自动全屏**：`settings:set({ autoFullscreen })` 落盘；`main/index.js` 在 `win.once('ready-to-show')` 里按设置 `win.setFullScreen(true)` 后再 `win.show()`（避免先显示再跳全屏的闪烁）。

两个选项在主进程 `settings` 默认值、渲染端 `App.state.settings` 默认值里都声明为 `false`。
