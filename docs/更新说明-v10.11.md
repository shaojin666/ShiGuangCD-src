# ShiGuangCD v10.11 更新说明（多语言）

本轮给整套界面加了**多语言**：设置里选一次语言，全应用（含桌面悬浮歌词、全屏歌词演出层、主进程弹出的提示）立刻换成该语言，**播放不中断**。支持 **简体中文 / 繁體中文 / English / 日本語 / Русский** 五门语言。

---

## 一、语言选择器（设置 · 外观）

- 位置：**设置 → 外观 → 界面语言**，排在主题之前——它是「整窗观感」的一部分。
- 选项一律用**各语言自己的写法**（简体中文 / 繁體中文 / English / 日本語 / Русский），不翻译成当前语言；否则用户看不懂哪一项是自己要的。
- 选中后**立即生效**并写入 `settings.json`（键 `lang`），重启保持。
- 语言在**首屏渲染之前**就已确定（`App.init` 里先读 `settings:get` 再建界面），不会先闪一下简体中文再跳。

## 二、词条与取词

- 新增 `renderer/js/i18n.js`：**5 份词典 × 441 个词条**（共 2205 条），键集合严格对齐。
- 取词 API：`T('key', { n: 12 })`，占位符写 `{n}`；命名空间为 `common.* / app.* / mode.* / chip.* / scene.* / needDisc.* / toast.* / set.* / library.* / notice.* / np.* / album.* / edit.* / fl.* / theme.* / float.*`。
- **回退链**：当前语言 → 简体中文 → key 本身。任何一门语言漏译都不会露出键名，也不会空一片。
- **语言 id 归一化**：`en-US → en`、`zh_CN → zh-CN`、`zh-Hant/zh-HK/zh-MO → zh-TW`，未知值回落简体中文。
- `<html lang>` 跟着切（`zh-TW` 写 `zh-Hant`），给 CSS 断词与朗读器用。
- 静态文案在 HTML 上用 `data-i18n` / `data-i18n-title` / `data-i18n-aria` / `data-i18n-placeholder` 标注，`I18n.apply()` 统一回填，新增文案不需要写 JS。

## 三、切换语言时的重排策略（不打断播放）

统一入口是 `App.setLang()` → `I18n.setLang()` → 广播 `relayoutLang()`：

| 区域 | 做法 |
| --- | --- |
| 顶栏 / 导航 / 各类按钮 | `I18n.apply()` 原地回填文本与 `title` / `aria-label` |
| 正在播放 | `NowPlaying.rerender()` 整页重建（DOM 只构建一次的老规矩不变） |
| 音乐库 / 专辑详情 | `Library.render()` / `Album.applyLang()` 重建 |
| 设置面板 | `SettingsPanel.refresh()` 重建，**并保持当前分类页**（不会跳回第一页） |
| 编辑面板 | `Edit.refresh()` 重建（表单值保留） |
| 全屏演出层 | `FlStage.applyLang()`：外壳按钮**原地回填**（不重建 DOM，避免丢监听器与主题挂载），主题面板 / 选歌面板 / 小胶囊各自重建 |
| 桌面悬浮歌词 | 独立窗口，主进程经 `float:lang` 推新语言过去 |
| 主进程提示 | `cd:notice` 载荷新增 `key` + `vars`，渲染端按当前语言取词；`text` 保留简体中文作兜底 |

**关键纪律**：整条链路只动文本与 DOM，**不碰 Transport / 播放引擎 / IPC 播放指令**——切换语言时音乐照放，进度不停，歌词行号不跳（已在测试中显式断言）。

## 四、主题名 / 参数名不再三处各写一份

主题的名称、描述、参数标签原先分别硬编码在 `fl-themes.js`、`fl-theme-mirror.js`、`fl-panel.js` 三处。本轮统一为：主题 `def` 上挂 `nameKey / descKey`，参数挂 `labelKey`，界面一律走 `FlThemes.nameOf() / descOf() / paramLabel()`。中文 `name / desc / label` 保留作兜底（词典缺项或调试直接读 `def` 时仍可用）。

# 后续修补（v10.12）

## 一、俄文设置分类顶出边框

**现象**：把界面语言切到俄文，设置面板左栏的「Воспроизведение」直接压过右边框、叠到内容区上，「Полноэкранный текст」「О программе」也贴着边。

**根因**：侧栏 `.set-nav` 写死 `width: 150px`，减去内边距与图标后留给文字的只有 **69px**；而「Воспроизведение」在 12.5px / 0.08em 字距下实测 **118px**（DejaVu 度量，比 Windows 的 Segoe UI 更宽）。flex 子项默认 `min-width: auto`，长单词既不肯缩也不肯断，只能顶出去——这是「按中文长度定的宽度」遇到屈折语长词的经典失配。

| 语言 | 最长分类 | 文本宽 | 原可用宽 | 结果 |
|---|---|---|---|---|
| 简体 | 全屏歌词 | 54px | 69px | 正常 |
| English | Appearance | 77px | 69px | 溢出 8px |
| Русский | Воспроизведение | 118px | 69px | **溢出 49px** |

**改法**（`renderer/css/panels.css`，只动设置面板，不碰通用 `.panel-body`）：

1. 侧栏 150 → **180px**，内边距 `0 12/24` → `0 10/18`，图标间距 9 → 8px：给文字腾出 112px；
2. `.set-nav-item > span` 加 `min-width: 0` + `overflow-wrap: break-word` + `hyphens: auto`——**最后一道保险**，以后加德语/芬兰语也不用再改宽度；
3. `html[lang="ru"] .set-nav-item` 单独把字距收到 0.01em、字号降 0.5px：西里尔字母在 0.08em 下比拉丁字母更占地方，收紧后「Воспроизведение」降到 101px，一行放得下。

**验证**：Chromium 无头实测五种语言 × 6 个分类共 30 项，最大溢出 **0px**（改前 49px）；仅「Полноэкранный текст」在词边界自然折成两行。`ui-contract` 新增 3 条断言把这三处样式钉住，防止以后有人把宽度改回 150px。

### GSAP 的许可冲突（已解决）

`renderer/js/vendor/gsap.min.js`（3.13.0）是 GreenSock 的**专有**许可（Standard "No Charge"），
既不属 OSI 开源，也不与 GPL 兼容 —— GPLv3 要求整个作品都能按 GPLv3 再分发，
而 GSAP 不允许被重新授权。**已按下一节所述移除 GSAP**，随包组件里不再有 GPL 不兼容项。

Three.js（MIT）、Electron（MIT）、koffi（MIT）均已确认与 GPLv3 兼容。

## 三、动画：移除 GSAP，换成 213 行自有补间

GSAP 的许可与 GPLv3 不兼容（见第二节），而它在项目里其实只干了同一件事——
**把某个数值从 A 插值到 B，带一条缓动曲线**。全量统计：9 次 `fromTo` + 11 次 `killTweensOf`，
timeline / 插件 / scroll / FLIP / morph **一个都没用**。

| 调用点 | 目标 | 补间 | 时长 / 缓动 |
|---|---|---|---|
| 流光 | `--fl-pop` | 0.9 → 0 | 0.55s power2.out |
| 倾诉 | `--fl-whisper-breath` | 1 → 0 | 1.2s sine.out |
| 倾诉（入场） | `--fl-whisper-y` + `opacity` | 10→0 / 0→1，**stagger 0.055** | 0.75s power2.out |
| 回环 | `--fl-orbit-kick` | 1→0（换行）/ 2.6→0（入场） | 0.7s / 1.1s power3.out |
| 群唱 | `--fl-chorus-slide` | 1 → 0 | 0.85s power2.out |
| 凝彩 | `--fl-prism-flare` | 1 → 0 | 0.9s power2.out |
| 运镜 rig | JS 对象 `cut`（5 通道）/ `intro` | → 0 | 1.15s / 1.5s |

新增 `renderer/js/tween.js`（213 行 / 8.5KB，gzip 3.6KB；零依赖）：

- **两种目标**：元素（每帧 `style.setProperty`，与 GSAP 完全同一写入通路）/ 普通 JS 对象（每帧改属性）。
- **缓动逐点一致**：`power2/3/sine` 用多项式实现（`1-(1-t)^3` 等），与 `gsap.parseEase()` 100 点采样
  比对最大偏差 **0**（power2/power3）、**2.4e-16**（sine，浮点噪声）。
- **不碰 `transition`**：这点很关键 —— `.fl-line` 自带 `transition: opacity .28s, font-size .35s,
  color .35s`，若用「`@property` + transition」做补间，内联 transition 会把这三条整个覆盖，
  行的淡入会突然变成硬切。所以这里刻意选了 style 写入（也就是 GSAP 原本的做法）。
- **打断语义**：同一目标再次 `fromTo` 即「打断重来」，等价 `killTweensOf + fromTo`，11 处 kill 调用随之消失。
- **`clearProps` / `reset`**：补间结束移除内联 `opacity`；切主题时 `reset()` 抹掉内联变量，
  回落到 CSS 的 `var(--x, 0)`。

**真浏览器 A/B**（Playwright + Chromium，同一页面同一时钟，同参数同写法，0.6s 补间）：
逐点最大互差 **0.0027**（满量程 1.0 的 0.3%），差异来自子帧相位，曲线形状一致。

**代价（诚实说明）**：浏览器不再替我们跑时间轴，主线程卡住时补间会一起卡——
但这正是 GSAP 版本原本的行为（GSAP 同样跑在主线程 rAF 上），所以没有性能回退；
换来的是 71KB → 0KB、零许可风险、以及一套能看懂的代码。
