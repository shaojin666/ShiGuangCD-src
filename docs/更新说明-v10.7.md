# ShiGuangCD v10.7 更新说明

本次更新对应用户实测反馈的 **7 项需求**：TTML 对唱/背景歌词排版改为 amll 风格（含背景歌词字号与逐字修复）、悬浮歌词撤掉整窗长按拖动并补主对唱左右区分、专辑详情页曲目高亮实时更新、方形封面"方容器包圆图"修复与唱片中心孔开关、音乐库右键移除加确认、音乐库右下角退碟/弹托盘按钮、左下角全字段搜索。文末另附**交付后实测两处小瑕疵的修复**（搜索空态残留叠加、方形模式迷你唱片被误伤）。变更共涉及 **21 个文件**（13 个源码 + 6 个测试 + package.json 版本号 + 本说明，其中 `tests/v10.7.test.js` 与 `tests/library-empty.test.js` 为新增）。

## 需求 1：对唱 / 背景歌词排版（amll 风格）

用户原话：整首无对唱 → 所有歌词居中；含对唱 → 所有非对唱（主唱）靠右、所有对唱靠左、无任何居中；背景声歌词跟随所属行（对唱歌词下方靠左、主唱歌词下方靠右）。另外背景歌词逐字效果似乎消失、字体偏小且不受设置里的歌词大小控制。

### 1a. 歌曲级对唱判定（模型层 + 渲染层双实现）

- **`main/metadata/lyrics-model.js`**：新增导出 `analyzeDuet(model)`。判据覆盖两种对唱形态：① 折叠对唱——主行 `bg` 里出现带 `agent` 的条目（时间重叠的双声部）；② 交替对唱——≥2 个不同 `agent` 的主行。`mainAgent` **只按主线 agent 频次取**——折叠后对唱方的主线已并入宿主 `bg`，若把 bg 条目也计入频次，会把对唱方误判成主唱、宿主行反而靠左（左右颠倒），这是实现过程中实测抓到并修掉的坑。
- **`renderer/js/lyrics-view.js`**：`analyzeDuetLocal(m)` 与主进程同规则（渲染端不跨进程取），`load()` 时按整首歌判定，容器切换 `.duet` 类；导出 `duetInfo()` 供悬浮窗取同一结构。

### 1b. 行级 / 条目级分类与 CSS 左右规则

- **类名链路**（`lyrics-view.js` `buildLine`）：对唱主行（自身 agent ≠ mainAgent）打 `duet-line`；bg 条目带 agent 打 `bg-duet`，无 agent 的 x-bg 打 `bg-main`（跟随宿主行）；无对唱的歌两个类都不打。
- **`renderer/css/pages.css`**：`.np-lyrics.duet .lrc-line { text-align: right }`（非对唱全靠右）、`.duet-line` 及其 bg 靠左、`.bg-duet` 靠左、bg 默认靠右。**废弃 v10.6 的 `has-bg`（主左对右）方案**——用户反馈方向与 amll 相反。
- **背景歌词字号**：`.lrc-bg` 从 `calc(var(--lyric-base) * 0.62)`（不乘 `--lyric-scale`，即"不受设置控制"）改为 `calc(var(--lyric-base) * 0.78 * var(--lyric-scale))`——逐字管线本身完好（jsdom 实测验证过），感知"逐字消失"的根因是字号小 + 填充两端色对比弱，现在字号加大且跟随设置。

### 1c. 对唱行的背景人声平铺（模型层）

`foldDuetLines` 原来只把对唱主线折进宿主 `bg`，对唱行**自带的 x-bg** 会随之丢失。现在紧随其后平铺进宿主 `bg`，每条盖 `agent: line.agent`（跟随对唱一侧）。用平铺而非嵌套 `bg.bg`，是为了过 `lyricsDataModel` 的 schema 白名单（嵌套结构落盘即丢）。

## 需求 2：悬浮歌词（撤拖动 + 主对唱区分 + bg 逐字）

- **移除整窗长按拖动**：用户实测拖中间会把窗口拉伸，决定放弃该功能，只保留顶部拖动条。全链路清除——`renderer/js/floating.js`（DRAG_HOLD_MS / 抖动容度 / beginDrag / plate 六个指针监听）、`main/floating.js`（`float:move-start/move/end` 三个 handler + moveAnchor）、`preload.js`（白名单）、`renderer/css/floating.css`（`body.dragging`）。四角把手缩放不受影响。
- **主对唱左右区分**：`buildCurrentLine` 按 `info.agent` 与 `info.duet.main` 打 `duet-line`；bg 块打 `bg-duet / bg-main`；`main/floating.js` 的 `setLyrics` 白名单放行顶层 `agent` 与歌曲级 `duet {has, main}`，`nowplaying.js` 的 `emitLine` 从 `LyricsView.duetInfo()` 取结构随行推送。
- **bg 词级填充**：新增 `appendBgWords()`（与主线同构：`.bw` span + animation-delay/duration + `.sung` 终态），跑 `bw-fill` 补间（终点亮度比主线暗一档），不再静态展示；`.bg` 字号从 0.6 档加大到 0.72 档。

## 附：交付后实测两处小瑕疵的修复（1.6.1）

### 瑕疵 1：搜索空态残留且反复叠加

用户原话：搜索无结果时背景显示"无结果"，但关闭搜索后空态始终显示；每触发一次无结果就多叠一个，界面背景混乱。

**根因**（`renderer/js/library.js` `rebuildItems()`）：CoverFlow 模式下空态 `.lib-empty` 是挂在 `container`（`#lib-flow` 视口）上的，而清理逻辑只做 `flowRow.innerHTML = ''`——`flowRow` 只是 container 的子元素，旧空态永远清不掉：无结果重建一次就多叠一个，关闭搜索后重建（此时有结果）也只清 flowRow，残留空态一直挂在背景上。原版网格模式走 `container.innerHTML = ''` 所以没这个问题。

**修复**：`rebuildItems()` 在清行之前先把 container 上的陈旧 `.lib-empty` 全部摘掉（两种视图模式都生效，幂等）。

**回归**：新增 `tests/library-empty.test.js`（jsdom 驱动真实 library.js，走 `setStyle → render → refresh → rebuildItems` 全链路）——空库恰好 1 个空态、反复 refresh 不叠加、无结果搜索只 1 个且再次触发不叠加、Esc 关闭搜索后空态消失且条目恢复、有匹配正确过滤、grid 模式同样不叠加，共 19 个断言。

### 瑕疵 2：方形模式下传输条左下角的迷你唱片被改成"圆包方"

用户原话：方形模式下播放界面左下角的唱片变成了圆形内部包着方背景，希望方形模式下左下角唱片不受影响，还是圆形。

**根因**（`renderer/css/pages.css`）：`.disc-face / .disc-spin / .disc-hole` 是**通用类**——主唱片（`.np-disc` 内）与传输条左下角的迷你唱片（`.np-mini-disc` 内，46px 小圆盘、`overflow: hidden`、自带一套同名的圆形规则）共用。v10.6 / v10.7 新增的方形规则（`#page-nowplaying.cover-square .disc-*`）没有限定作用域，把迷你唱片也一起改了：外框 `.np-mini-disc` 仍是 `border-radius: 50%` 的圆，里面的 `.disc-face / .disc-spin` 却被切成 16px 方角、藏了中孔——就成了"圆容器包着方背景"。

**修复**：所有方形 / 中心孔规则一律收窄到 `.np-disc` 作用域（含 v10.6 遗留的去纹路 / 停转 / 藏中孔与 v10.7 的 16px 方角化、`.no-hole`）：

```css
#page-nowplaying.cover-square .np-disc .disc-face  { /* 去纹路 */ }
#page-nowplaying.cover-square .np-disc .disc-spin,
#page-nowplaying.cover-square .np-disc .disc-face  { border-radius: 16px; }
#page-nowplaying.cover-square .np-disc .disc-spin  { animation: none; }
#page-nowplaying.cover-square .np-disc .disc-hole  { display: none; }
#page-nowplaying.no-hole         .np-disc .disc-hole { display: none; }
```

迷你唱片（传输条常驻）在任何封面模式下都保持圆形、旋转、带中孔。

**回归**：`tests/v10.7.test.js` D 段断言全部改为带 `.np-disc` 的新作用域，并新增反转断言——`cover-square / no-hole` 下不得出现无作用域的 `.disc-face / .disc-spin / .disc-hole` 规则（防止未来再漏穿迷你唱片）；`tests/v10.6.test.js` G 段同步。
