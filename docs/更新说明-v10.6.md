本次更新对应用户反馈的 **1 个阻塞性 Bug + 4 大项调整需求**：专辑详情页二次打开失效（三残留 + 一竞态）、详情页背景取色导致的可读性问题、进度条/音量条精准可视化与滚轮调速、歌词四小项调整（罗马音大小 / 对唱左右分布 / 悬浮歌词背景歌词与英文空格 / 整窗拖动与译音开关）、播放页方形封面样式。变更共涉及 **17 个文件**（13 个源码 + 4 个测试，其中 `tests/v10.6.test.js` 为新增）。

## Bug：专辑详情页只在软件第一次启动时可用

用户实测：点击专辑进入详情页，Esc 退出后再次点击——页面"闪一下消失"，不显示但组件可点击（点空白处能切歌），Esc 可退出并恢复正常，必须重启软件。

排查确认这是**三类残留叠加一次竞态**，任缺其一都不会复现：

### 根因 A：`.closing` 的 `forwards` 填充模式把页面钉死在 opacity:0

`.album-overlay.closing` 的退场动画 `animation: albumout 0.24s ease forwards` 带 fill-mode——动画结束后元素**保持**在 100% 关键帧（`opacity: 0`）。而关闭收尾的 `finish()` 只加了 `.hidden`（`display: none`），**从未移除 `.closing`**。于是二次打开时 `display: none → block` 重启入场动画，闪 0.24s 后被 `forwards` 重新钉回 `opacity: 0`——页面看不见，但 `opacity: 0` 不拦指针事件，所以"组件能点击"。

**修复**（`renderer/js/album.js`）：`open()` 与 `finish()` **双向清理** `.closing`（连同 `has-colors` / `has-art` 与 `--al-c1/--al-c2/--al-scrim-a/b` 取色变量）。

### 根因 B：关闭 FLIP 在 `.al-art` 上留下行内 `opacity: 0`

关闭时专辑图飞回来源卡片，终点态（`opacity: 0` + 位移 + 缩放）是**行内样式**，`finish()` 不清。二次打开时 `flipIn()` 只在有来源卡片时才重写行内样式；即便重写，起点也继承自上次的终点。

**修复**：新增 `resetArtInline()`，清掉 slot 内 `.al-art` 的 `transition / transform / opacity` 行内样式，`open()` 与 `finish()` 都调用。

### 根因 C：430ms 的旧 `finish` 把新打开的页面重新盖上 `.hidden`

关闭动画用 `setTimeout(finish, 430)` 收尾。若用户在动画播完前再次打开详情页，旧的 `finish` 迟到触发，给**新页面**盖上 `.hidden`——正是"闪一下消失"的直接观感。

**修复**：引入**打开代次（epoch）**——`open()` 时 `epoch++`，`close()` 捕获 `myEpoch = epoch`，`finish()` 校验 `myEpoch !== epoch` 即作废（只复位 `closing` 标志，不碰 DOM）。竞态窗口彻底关闭。

### 回归固定

`tests/v10.6.test.js` **#A** 用静态契约固定三条清理路径 + epoch 守卫（含"open/finish 都必须摘 `.closing`"这类易回归点）。

## 需求 1：详情页可读性——智能文字颜色

用户实测：黑色专辑封面下，取色背景与文字糊在一起无法阅读。原有背景完全跟随封面取色，没有可读性保障。

**修复三层**（`renderer/js/album.js` + `renderer/css/pages.css`）：

1. **取色亮度压制**：新增 `clampForText(c, 0.22)`——过亮的取色按比例线性压到感知亮度 ≤ 0.22（保色相），径向渐变核心不再吞文字；
2. **暗色 scrim 兜底**：无取色（或浅色主题）时把 scrim 加到 `0.86 / 0.95`，并写进 CSS 变量 `--al-scrim-a/b`（`.al-bg-tint` 带 var() 兜底，JS 未到位前也有一层暗底）；
3. **智能文字色板**：`applyTextPalette()` 按"有效背景亮度"（0.72×scrim + 0.28×取色加权）在亮/暗两套文字色板间切换，写入 `--al-fg / --al-fg-dim / --al-fg-faint / --al-hover / --al-line` 五个变量；详情页所有文字元素（标题 / 曲目 / 时长 / 介绍 / 徽章 / 关闭钮）改消费这套变量，并加 `text-shadow` 兜底。

同时把详情页的 chrome（`--glass / --line / --surface-3 / --accent-strong`）强制覆写为暗色一套——浅色主题下这些亮色 chrome 糊在暗底上同样不可读。

## 需求 2：进度条 / 音量条精准可视化 + 音量滚轮调速

- **悬浮提示**（`renderer/js/nowplaying.js`）：native range 没有 hover 事件，用 `getBoundingClientRect()` + `clientX` 算比例；鼠标在进度条上移动时，光标上方实时显示**对应时间**（`fmt(sec)`），音量条显示**百分比**。提示气泡 `.slider-hint` 为 `position: fixed` + `translate(-50%, -100%)`，`pointer-events: none`，跟随鼠标。
- **音量滚轮**：`wheel` 监听必须 `{ passive: false }` 才能 `preventDefault`（否则会连带滚动页面）；每格 ±4%，调完在滑块当前位置浮一下读数（900ms 自动隐藏，`_hintTimer` 防重入）。

## 需求 3：歌词调整（四小项）

### 3a. 设置页新增罗马音歌词大小

`roScale` 全链路（`renderer/js/app.js` Sizes 架构 + `renderer/js/settings.js` 滑条 + `main/index.js` 默认值 + `renderer/css/pages.css` 的 `.lrc-ro` 消费 `--lyric-ro-scale`）。范围 0.6~1.8，与翻译档一致；恢复默认按 keys 遍历，四个滑条一起复位。

### 3b. 对唱歌词主左对右（主界面 + 悬浮歌词）

- 主界面（`renderer/js/lyrics-view.js` + `pages.css`）：有背景人声的行加 `.has-bg` 类，`text-align: left`，对唱块 `.lrc-bg` 单独 `text-align: right`；**无对唱的行仍居中**。
- 悬浮歌词（`renderer/js/floating.js` + `floating.css`）：同样语义，`.line.has-bg` 主左 / `.bg` 对右。
- 为什么用 `text-align` 而不是 flex：当前行里混着逐字填充的词 span 与"当前行圆点"行内元素，改 flex 会把整行排版打乱。

### 3c. 悬浮歌词补背景歌词 + 英文空格 + 整窗长按拖动 + 译/音开关

- **背景歌词**：管线补齐——主界面 `emitLine` 推 `info.bg`（文本 + 词级时间轴）→ 主进程 `setLyrics` 白名单（bg ≤ 6 条、词 ≤ 120、字段逐个校验）→ 悬浮窗渲染 `.bg` 块（右对齐）。此前悬浮窗完全不显示对唱。
- **英文空格**：主界面 v10.5 已修（`needsSpace` 启发式），悬浮窗**同规则移植**——拉丁词之间补空格文本节点，CJK / 连字符两侧不补。
- **整窗长按拖动**：见下方专节。
- **译 / 音开关**：设置页新增「悬浮歌词显示翻译」「悬浮歌词显示罗马音」两个开关（默认开），走 `app:set-float-show` IPC → 主进程 `setShowOpts`（落盘 + 立刻推送）→ 悬浮窗 `float:opts` → `body.no-tr / no-ro` 类控制 `.tr / .ro` 显隐。只切 display、不重建歌词节点。

### 3d. 悬浮歌词整窗长按拖动（技术说明）

用户要求"整个窗口长按都可以拖动"。这里**没有**把整个底板设为 `-webkit-app-region: drag`——drag 区域的鼠标事件不会送给页面，会把悬停显控件、中键锁定全部废掉（控件条将永远无法唤出）。改为与缩放把手**完全同款的安全路径**：

- 渲染端（`renderer/js/floating.js`）：底板 `pointerdown`（左键、非四角把手、非锁定态）→ 按下即 `setPointerCapture`（光标移出窗口不丢手）→ 300ms 长按阈值（`DRAG_HOLD_MS`）内抖动不超 8px 才进入拖动态（短按仍是点击，中键锁定不受影响）；拖动中 `requestAnimationFrame` 合帧，每帧最多一次 IPC；
- 主进程（`main/floating.js`）：`float:move-start / move / move-end` 三个通道，**锚点 + 系统光标绝对坐标**重算位置（`screen.getCursorScreenPoint()`），不用增量累加、不用渲染端坐标——这正是早年那套"拖着拖着窗口自己变形"的自绘拖动被整段删除的原因，新实现不重蹈；只改位置不改尺寸，逐帧不落盘、松手一起写。

顶部拖动条保留为"快速一拖就走"的捷径。拖动态有全局 `cursor: grabbing` 反馈。

## 需求 4：播放页方形封面样式

设置页「播放页封面样式」分段控件：**唱片**（默认，原旋转黑胶）/ **方形**。

- 方形语义（`renderer/css/pages.css` 的 `#page-nowplaying.cover-square` 作用域）：方角 16px、停转（`animation: none` 压过 `.is-spinning`）、藏中孔、去光盘纹路（改用"有封面"的简洁内描边）、背后辉光同步变方；
- **暂停缩小 / 播放放大**：缩放挂在 `.np-disc-slot` 上（`.np-disc` 在换碟交接时会被 JS 写行内 transform，不能承载状态缩放），`playing` → `scale(1)`，`paused / stopped` → `scale(0.9)`；
- **非线性动画**：`transform 0.45s cubic-bezier(0.34, 1.56, 0.64, 1)` 回弹曲线；圆角也进过渡，唱片↔方形切换时是"圆角长出来"而非硬跳；
- 链路：`settings.js` 分段控件 → `App.setCoverStyle`（即时生效 + `settings:set` 落盘）→ `NowPlaying.setCoverStyle` 切类；`main/index.js` 默认 `coverStyle: 'disc'`，升级用户无感。
